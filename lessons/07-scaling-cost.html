本章缩写：GPU-h = GPU hours（GPU 时：GPU 数 × 小时数）；SONIC：NVIDIA 的通用动作跟踪器（论文名 Supersizing Motion Tracking 的缩写）；L40、H100：两种 NVIDIA 数据中心 GPU；DAgger = Dataset Aggregation（数据集 / 聚合，一种蒸馏方法）。全部缩写见 附录 · 缩写与术语表

讲解

第一步：两条扩展路线（2026-11-20）

类比：培养一支全能舞团。 办法一：每支舞请一位专家各练一个徒弟，再让一个总徒弟跟所有专家学（会丢东西）。办法二：一个徒弟同时学所有舞，靠堆训练时间。

路线 代表 做法 代价
专家 + 蒸馏 BeyondMimic 每条动作训一个 PPO 专家，再用 DAgger 蒸馏成一个策略 蒸馏有损（SuperMimic 原话 "lossy distillation"）
暴力通用策略 SONIC 一个 PPO 策略吃所有动作 集群级算力

两条路都证明了：动作库越大，控制器越强。但都越扩越贵（L57–L63）。

一句话：要么专家蒸馏有损，要么一个策略硬堆算力。

第二步：算一下 SONIC 的账（2026-11-20）

SONIC 的 scaling 实验（sonic-2511.07820.txt L268–L269）：把 GPU 从 16、32 加到 128 张，各训到 5 万次迭代，约 2k、9k、21k GPU-h；数据 700 小时动捕、1 亿帧。SuperMimic §4.1 引用的最终版本：

GPU 时间 GPU-h
SONIC 128 张 L40 168 h（7 天） 128 × 168 = 21504
SuperMimic 1 张 H100 3 h 1 × 3 = 3

GPU-h 比 = 21504 / 3 ≈ 7168 倍（论文写「超过 1000×」，保守说法）；墙钟比 = 168 / 3 = 56 倍（论文写「超过 50×」）。3 小时的那个点，SuperMimic 在同一套 12.9 万条动作上的归一化回报已经超过 SONIC 公开的 checkpoint，失败动作数 25 对 179。

一句话：两万多 GPU 时 vs 3 GPU 时，差七千倍。

第三步：这个比较公平吗（2026-11-20）

论文自己在「Compute accounting」（L329–L337）里列了两处不对等，都对 SuperMimic 有利：

不对等 倍数
数据：SuperMimic 只用 BONES-SEED 公开子集 264.56 h，SONIC 用 611 h 611 / 264.56 ≈ 2.31
硬件：H100 的 tensor-core 峰值是 L40 的 5.5 倍（fp32 只有 0.74 倍） 最多 5.5

把这两项全算给 SONIC：2.31 × 5.5 ≈ 12.7，7168 / 12.7 ≈ 564 倍。还剩两个多数量级，所以「1000× 以上」的说法偏乐观，但「几百倍」站得住。另外，失败数是在训练集动作上测的，衡量的是覆盖度，不是泛化（附录 F.2）。

一句话：扣掉数据和硬件的优势，仍差五百多倍。

第四步：为什么 PPO 扩数据就是扩算力（2026-11-20）

类比：一百个学生学一百支舞，但他们其实都在学同一副身体怎么动。如果每个人都从头摸索「这样蹬地会怎样」，就浪费了一百遍。

SuperMimic 的诊断（L61–L62）：所有动作都由同一个身体执行，共享同一套刚体和接触动力学；model-free 的 PPO 不显式建模这份共享结构，每条动作都要从带噪声的仿真回放里重新估计「这个动作会带来什么后果」。

受控实验（LAFAN1 40 条动作，L344–L346）也说明瓶颈不在卡数：

方法 结果
PPO-Sim 1 / 4 / 8 GPU，18 h 最终回报 0.60 / 0.70 / 0.72（4 → 8 卡几乎不涨）
SuperMimic 1 GPU 1.2 h 到 0.82

PPO-Sim 和 SuperMimic 用同样的动作、观测、奖励、终止、域随机化和网络大小，每卡环境数还是 SuperMimic 的两倍。差别只在「梯度从哪来」，这是第 8 章的主题。

一句话：每条动作都在重新摸索同一副身体的物理，加卡只是摸索得更快，不是更聪明。

数学原理

  • 对数坐标：每格乘 10，适合比较相差几个数量级的数；log₁₀ 21504 ≈ 4.33，log₁₀ 3 ≈ 0.48，差约 3.85 格。
  • 倍数的合并：几个独立因素的倍数相乘（2.31 × 5.5），要扣掉就相除。

公式清单

公式 意思
GPU-h = GPU 数 × 小时 算力账
21504 / 3 ≈ 7168；168 / 3 = 56 GPU-h 比、墙钟比
7168 / (2.31 × 5.5) ≈ 564 扣掉数据和硬件后的差距

讲义 ↔ 代码（数字全部来自 SuperMimic §4.1）：

讲义 公式 写法 跑出来
第二步 GPU-h GPU × 小时 ratios() 21504、3、7168×、56×
第三步 修正 ÷ (2.31 × 5.5) leftover_gap(7168) ≈ 564×
第四步 PPO 加卡 — main() 第三段 0.60 / 0.70 / 0.72 vs 1.2 h 到 0.82

关键几行：

a, b = gpus_sonic * hours_sonic, gpus_sm * hours_sm    # 21504 vs 3
ratio = a / b                                          # ≈ 7168
leftover = ratio / ((611 / 264.56) * 5.5)              # 把数据、硬件优势都还给 SONIC

代码里才看得到的 1 件事：

  • 论文只写「超过 1000×」「超过 50×」，是保守的下界；代码给的是精确比值 7168 和 56。讲义按精确值算，按论文的保守说法下结论。
